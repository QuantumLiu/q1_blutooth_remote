# Magicsee R1 遥控器验证记录

记录日期：2026-11-09

本文件记录 Magicsee R1 手柄在 Q1 上的实测结果，供排查键位和模式问题时参考。安装和日常使用见仓库根目录的 `README.md`。

## 1. 结论

- Magicsee R1 可以通过标准蓝牙 HID 接入 Q1，按键和方向轴均可被 Linux 输入系统读取。
- 游戏模式下方向使用 `ABS_X/ABS_Y` 轴，A/B/C/D/O 使用手柄按键；普通模式和鼠标模式的键码完全不同。
- 已完成站起、趴下、走跑控制、横移、转向和语音启动的实机验证。
- 手柄的 A+B、M+O 组合不会作为组合上报，因此站起/趴下使用 O 键序列，不使用双键组合。

## 2. 设备与输入节点

| 项目 | 内容 |
| --- | --- |
| 手柄名称 | `Magicsee R1` |
| 蓝牙地址 | `<R1_BT_ADDR>`（本地配置，不提交） |
| 协议 | 标准 Bluetooth HID |
| 配对状态 | 已配对、已信任、已连接 |

连接后生成四个输入节点，编号以实际系统为准：

| 节点 | 设备名 | 用途 |
| --- | --- | --- |
| `/dev/input/event0` | `Magicsee R1 Consumer Control` | 媒体键、音量键 |
| `/dev/input/event1` | `Magicsee R1` | 游戏模式的方向轴和 A/B/C/D/O |
| `/dev/input/event2` | 鼠标 | 鼠标模式 |
| `/dev/input/event3` | 键盘 | 键盘模式 |

控制器按 `Name` + `Uniq`（蓝牙地址）查找节点，不写死 `eventN`。换机器或重新连接后节点编号变化不影响使用。

游戏模式下所有有效事件都来自 `Magicsee R1` 节点，其他三个节点没有事件。

## 3. 模式切换

按说明书使用 `M + A/B/C/D` 切换模式。三种模式的实际输出差异很大：

| 模式 | 方向 | A | 用途 |
| --- | --- | --- | --- |
| 普通模式 | 方向键键码 | `KEY_PLAYPAUSE (164)` | 不用于本项目 |
| 鼠标模式 | Consumer Control 键码 | `BTN_SOUTH (304)` | 不用于本项目 |
| 游戏模式 | `ABS_X/ABS_Y` 轴 | `BTN_WEST (308)` | 本项目使用 |

切换模式后建议用 `./scripts/run_key_capture.sh` 复核键码。手柄重连、换电池或长时间休眠后可能回到默认模式，这是“语音启动成功但按键无反应”的常见原因。

## 4. 游戏模式实测键位

| 操作 | 事件 | 行为 |
| --- | --- | --- |
| 上 / 下 | `ABS_Y=0 / 2`，回中 `1` | 前进 / 后退 |
| 左 / 右 | `ABS_X=0 / 2`，回中 `1` | 左转 / 右转 |
| A | `BTN_WEST (308)`，附带 `BTN_TR2 (313)` | 向左平移；`313` 不分配功能 |
| B | `BTN_SOUTH (304)` | 向右平移 |
| C | `BTN_NORTH (307)`，附带 `BTN_TL2 (312)` | 招手 `Q_BECKON (3001)`；`312` 不分配功能 |
| D | `BTN_EAST (305)` | 碰拳 `Q_BUMP_FISTS (3003)` |
| O | `BTN_TL (310)` | 站起 / 趴下序列 |
| M | 与 O 相同或相邻键码，随固件变化 | 只用于模式切换，不参与控制 |
| 返回 | 未收到事件 | 不映射 |

说明：

- 方向轴每个方向只产生一次事件，没有 `value=2` 重复上报，也没有中间模拟量，属于三档数字量。
- A、C 会同时上报一个附加键码，控制器只使用主键码。
- M 和 O 的键码在不同固件上出现过变化。当前配置使用 O=`310`；如果采集结果不同，改 `config/remotes.json` 的 `action_keys`。
- 早期记录中的 M=`310`、O=`311` 已不再适用于当前手柄固件。

## 5. 组合键限制

实测组合操作不会按组合上报：

- 同时按 A+B：只上报 B=`304`，A 被丢弃。
- 同时按 M+O：只上报 O。
- 先按住一个键再按另一个键：仍只上报后按下的键。
- 底层 HID 原始报告与 `evtest` 结果一致，说明事件在生成前就没有作为组合上报，不是采集程序丢失。

因此控制器不能用 A+B 或 M+O 表达独立功能。站起/趴下改为 O 键序列：

1. 短按 O（≤0.8 秒）后松开。
2. 1.5 秒内再次按住 O ≥2 秒。
3. 语音询问，等待松开。
4. 15 秒内短按 O 确认。

## 6. rc 输入源冲突

系统常驻的 `rc` 进程会直接打开 `Magicsee R1` 的手柄节点，把按键和轴送进系统原有遥控链路。

实测现象：手柄连接后，机器人进入 `BIPED_WALK_RUN` 时出现自动前进，轴值当时为 0。进程文件描述符确认 `rc` 持有该输入节点。

处理方式：

- 档案中配置 `disable_sources: ["rc"]`。
- 控制器启动实机模式时调用 `SetMcInputSource` 禁用 `rc`，失败则拒绝运动。
- 退出时如果机器人仍站立或走跑，保持 `rc` 禁用；只有非运动状态才恢复。
- 不要在测试期间同时打开 APP 遥控或其他速度指令来源。

曾因自动前进强制拔电池重启。首次实机运行必须准备独立急停。

## 7. 语音监督服务验证

- 监督服务订阅 `/aima/agent/asr_result`，只处理 `is_final=true` 的结果，并按 `event_id` 去重。
- “启动R1遥控 / 启动R1遥控器”只连接已绑定手柄，然后启动控制器。
- “绑定蓝牙遥控器”在未绑定时搜索、询问、配对并记忆地址；已绑定时直接提示，不重复配对。
- 绑定流程不启动运动控制，绑定成功后需要再说“启动R1遥控”。
- 用模拟 ASR 结果验证了已绑定/未绑定分支、确认和取消流程，以及监督服务退出时子控制器被安全停止。
- 板载部署使用 `/robot/software/r1_remote` 和 process_manager 第二阶段启动项；安装前备份原配置，下次开机生效。

## 8. 云端语音冲突

- “连接蓝牙遥控器”被云端 NLU 固定映射为设备绑定任务，会播报验证码和绑定提示，无法只靠本地订阅 ASR 阻止。
- 本地精确技能入口在当前 `online_priority` 仲裁下没有生效，相关改动已撤销。
- 最终把连接指令改为“启动R1遥控”，绑定保留为独立指令。
- 监督服务在收到本项目指令后的 12 秒内订阅 `/interaction/tts_status`，对非本项目 `trace_id` 的播报调用 `StopTtsTraceId` 停止，避免云端无关回答打断操作。

## 9. 已验证与未验证

已验证：

- 手柄配对、连接和输入节点查找。
- 游戏模式方向、A/B、O 序列、C/D 键码采集。
- 无运动模式下的目标速度输出。
- 实机走跑、前进、后退、转向、站起、趴下。
- 横移在无运动模式下验证；实机横移请在防护环境确认。
- `rc` 禁用与控制权复核。
- 语音连接、绑定分支和开机监督服务部署。

仍需按实际固件确认：

- C/D 预制动作的实机幅度和结束状态；首次使用请在防护环境确认。
- 不同批次手柄的 M/O 键码和设备名。
- 长时间运行下的断连和重连行为。

## 10. 安全边界

- 默认 `execute:=false`，只打印速度。
- 实机模式必须显式开启，首次测试使用空旷场地、2 米安全距离和独立急停。
- 松开事件丢失或手柄断连时机器人可能持续运动，建议加 `event_timeout:=1.0`。
- 退出控制器不会自动恢复之前的运动状态，运控 Action 可能保持在 `BIPED_WALK_RUN`。
